# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static, no-build web app that helps a young child (~6yo) learn to recognize and recall written Kannada letters by sound. Plain HTML/CSS/JS — no framework, no bundler, no package.json, no dependencies.

## Running it

There's no build step. Serve the directory and open it:

```bash
python3 -m http.server 8000
# open http://localhost:8000
```

Opening `index.html` directly via `file://` mostly works but is not recommended — some browsers restrict `speechSynthesis`/canvas APIs on `file://`, so prefer the local server.

There is no test suite, linter, or build/lint/typecheck command in this repo. Verify changes by loading the page in a browser (or at minimum `node --check kannada/app.js` for syntax) and exercising the flow by hand.

## Layout: hub + sections

The root `index.html` (+ `home.css`) is a hub page listing learning sections as cards. Each section is a self-contained page in its own folder (currently only `kannada/`), linked with plain `<a href>` — no client-side router, so browser/phone back works natively and each section's script-scope globals stay isolated. `shared/theme.css` holds the common tokens (colors, font, body, `.hidden`, `.back-link`) and is loaded before each page's own stylesheet. To add a section: create `<name>/index.html` linking `../shared/theme.css`, add a `← All sections` back link (`href="../"`), and add a `.section-card` (with an `.age-badge`) to the hub. Use relative paths so the site works when served from a subpath.

`shared/words.js` is the kid-safe word list (`WORDS`: `{ word, emoji }`, plus `THEMES` for Word Hunt) shared by the word games — adding words there automatically creates more Busy Bee puzzles; word length is derived via `[...word]` so a future Kannada list of plain letters (no vowel signs/conjuncts, e.g. ಕಮಲ) can drop in. `word-guess/` is a Wordle-style game on top of it: 3- or 4-letter words, 6 tries, any guess accepted (no dictionary check, deliberately), QWERTY on-screen keyboard (switched from ABC order after the kids' feedback — don't revert), 💡 emoji hint after 3 misses, no persisted state. `word-hunt/` is a Strands-style word search: a random theme from `THEMES` (in `shared/words.js`), 4 words placed in a 5×5 grid in any of 8 directions (across/down/diagonal, forwards or reversed; crossing words never share a line axis), generated in-browser and rejected/retried if filler letters accidentally spell another theme word or a blocked word. Select by dragging or tapping letters in order, from either end (only a cell's round centre registers a drag, so diagonal drags don't clip neighbours); clue cards show the word's emoji + blanks, and tapping one glows that word's first letter. `busy-bee/` is a Spelling Bee-style game: a 5-letter "flower" (centre + 4 petals). Any real word counts — answers are every word in `busy-bee/dictionary.js` (`DICTIONARY`, ~5.5k common words of 3–8 letters, vetted to drop names, abbreviations, web jargon and grown-up words; `WORDS` are added at runtime) that uses only hive letters plus the centre. This replaced the old "only `WORDS` entries count" rule after the kids' feedback that real words like DARE were rejected — don't go back to a small list. Each hive is seeded from a word with exactly 5 distinct letters (so there's always a "whole flower" word and every petal is used) and kept only if it has 6–12 answers. Any other real word in `busy-bee/bonus.js` (`BONUS`, ~7.8k words from ENABLE ∩ the 50k most common English words, minus a bad-words list and a hand-picked grown-up list; only words with ≤5 distinct letters) is accepted as a "bonus word": cheered and listed under the cards, but no card and it doesn't move the bee — added after the kids still hit valid words being rejected. Each answer gets a clue card showing only blanks per letter (pictures were removed after the kids' feedback — don't re-add). Hints show one more letter of a word (never the last one): tapping a card hints that word, and the 💡 button hints the word with the fewest letters shown, so every first letter comes before any second letter. To block a word, delete it from `dictionary.js` (and `bonus.js`). `memory-match/` flips 8 picture↔word pairs from `WORDS` (≤4 letters, distinct emoji so no two pairs look alike). `groups/` is a Connections-style sort: 3 or 4 themes from `THEMES` (each needs a short `label`), 4 picture+word tiles each; a word is only dealt if it belongs to none of the other chosen themes, so list a word under every theme it fits (whale is in Animals too) or puzzles get ambiguous. No mistake limit, "so close" when 3 of 4 are right, 💡 names a group and selects one of its tiles. `scramble/` (Word Scramble) shows a word from `WORDS` with its letters mixed up (the picture is hidden behind `SHOW_PICTURE = false` in `app.js` after the kids' feedback that it gave the word away — kept, not deleted, so it can be flipped back); tap letters into the slots, tap a slot to send a letter back. Rounds of 10 words getting longer (2×3, 6×4, 2×5 letters — mostly 4 after the kids' feedback), distinct pictures per round. Only the pictured word wins; another real word from the same letters (checked against `busy-bee/dictionary.js`) gets "that's a word too, but not the one we want" (or "not this picture" when it's shown). 💡 locks in the next letter from the start, never the last. No persisted state. `what-next/` generates patterns in-browser: emoji repeats from `SETS` × `SHAPES` (AB, AAB, ABB, ABC, AABB, ABAC; capped at 8 items so the row never wraps) or counting sequences, always 3 distinct choices. `shared/confetti.js` + the game-UI bits at the bottom of `shared/theme.css` (`.icon-btn`, `.new-btn`, `.confetti`) are shared by the games. Avoid NYT trademark names (Wordle/Spelling Bee/Strands/Connections) for these games.

`ottakshara/` teaches vathakshara/ottakshara (joined letters) to a kid who already reads kagunita. `data.js` holds `OTTU_WORDS` (`{ parts, emoji, en }`, `parts` = the word split into syllables with spaces, e.g. `'ಬೆ ಕ್ಕು'`); `app.js` finds every letter + ್ + letter part itself and sorts it into a level by its letters: `same` (ಮ್ಮ), `diff` (ಸ್ತ, also ರ-ottu like ದ್ರ), `ark` (first letter ರ = arkavottu, ರ್ಯ). Rounds of 10 questions, one word each, mixing three types: pick the word from picture + speech, fill the missing joined part, or say which two letters make it; wrong choices are the typical slips (ottu left out, letters swapped) plus a different ottu. The Learn screen lists the words per level and has a build-your-own (any two letters + every vowel sign). Audio uses the same browser `speechSynthesis` approach as `kannada/`. Keep emoji distinct across words; no persisted state.

`olympiad/` is a mock-exam section for the Silverzone iOM Level 1 (Class 1) maths paper (the user's child is sitting it). `questions.js` holds `SECTIONS` (title, question count, marks each — mirrors the official pattern: 25 Qs, 100 marks, 40 min, no negative marking; re-check silverzone.org/Careers360 if the pattern changes) and one generator per question type; `makePaper(n)` seeds a mulberry32 rng from the paper number, so Paper n is identical every time. Generators return `{ prompt, options, answer, figure?, html?, small?, why? }`; figures are HTML/SVG strings built in code (clock, shapes, coins/notes, ribbons). Weight/capacity questions use tiers and keep the answer ≥2 tiers from every option so there's no arguable answer. `app.js` runs mock (timer, answers at end) or practice (instant feedback) mode; best score per paper persists in `localStorage` under `olympiad-scores-v1`. Verify generator changes by generating many papers in node and checking 4 distinct options + a valid answer index (the "which sign" question deliberately has 3: >, <, =).

## Files (Kannada section, all under `kannada/`)

- `data.js` — the single source of truth for content: `LETTERS`, an array of all 49 letters of the modern Kannada alphabet (13 vowels + 2 yogavaahakas + 34 consonants — deliberately excludes the archaic ಱ/ೞ). Each entry is `{ id, glyph, roman }`.
- `app.js` — all app logic (state, question selection, DOM rendering). One file, no modules (loaded as a plain `<script>`, so top-level `const`/`let` are just script-scope, not attached to `window`).
- `index.html` — three screens toggled via a `.hidden` class: `#home-screen`, `#browse-screen`, `#practice-screen` (which itself toggles between `#mc-screen` and `#recall-screen`).
- `style.css` — Kannada-specific styling on top of `shared/theme.css`; includes a `@media (max-width: 480px)` block for phones.

## Architecture: the adaptive quiz engine

This is the part that isn't obvious from skimming one file.

**Global phase, not per-letter.** There is exactly one active mode at a time — `globalPhase` (1 = multiple-choice, 2 = free-recall) — driven by *overall* streaks, not by any individual letter's history:
- 5 correct answers in a row (any letters, mixed) → promotes to phase 2.
- 2 wrong answers in a row while in phase 2 → demotes back to phase 1.
- This is intentionally asymmetric: hard to earn free-recall mode, easy to fall out of it.
- The Home screen also lets the user force a fixed mode (`appMode`: `'mc'` | `'recall'` | `'adaptive'`), bypassing `globalPhase` entirely. `resolveMode()` in `app.js` is the single place that reconciles `appMode` + `globalPhase` into the actual `currentMode` for the next question.

**Per-letter state is separate from phase**, and only drives *which letter* to ask next, not *how* (mc vs. recall). Each letter's `progress[id]` tracks `history` (last 5 correct/wrong outcomes) and `lastSeenIndex`. `pickNextLetter()` does weighted-random selection favoring letters answered wrong recently and letters not seen in a while — this is the spaced-repetition layer, independent of the phase state machine above.

**Free-recall mode has no handwriting recognition.** The kid draws on a canvas, taps "Show Answer" to reveal the correct glyph, then self-reports right/wrong (`self-yes`/`self-no`) — same trick Anki uses for cards that can't be auto-graded. Don't try to add real stroke/shape validation; that was a deliberate scope decision.

**Audio is live browser `speechSynthesis`**, not pre-recorded clips (`speakLetter()` in `app.js`), using `lang: 'kn-IN'` and picking any installed voice starting with `kn`. Quality is inconsistent across browsers/OSes and isolated single-character input is where general-purpose TTS engines are weakest (aspirated/retroflex consonants especially). A per-letter pronunciation-tuning UI was built and then deliberately reverted — the project owner wants to stay on default browser TTS until a better sourcing approach (real recordings or a paid neural TTS API) is decided; don't re-add tuning UI speculatively.

**LocalStorage schema** (`kannada-letters-progress-v2`): `{ letters: { [id]: { history: bool[], lastSeenIndex: number } }, globalPhase: 1|2 }`. The key was bumped to `-v2` when `globalPhase` moved from per-letter to global — bump it again if the shape changes, rather than trying to migrate old saved data. Stars/streak/accuracy counters are intentionally *not* persisted and reset on reload.
